Stream Credits

Scrolling end-of-stream credits overlay for OBS & Streamer.bot

View on GitHub

Overview

How it works

Three pieces work together. A Streamer.bot action counts emote usage across the stream. When you switch to your ending scene, a second action snapshots the top emotes to a JSON file. The OBS browser source then connects to Streamer.bot, fetches the viewer data and the emote file, and plays the scrolling credits.

Every chat message
Action 1 counts monkdr* emotes → persisted global
→
Scene change
Action 2 writes top 5 emotes to emotes.json
→
OBS browser source
Overlay fetches credits + emotes, animates scroll

Setup

Step-by-step guide

Add the OBS browser source

Add Scrolling Credits for SB.html as a browser source in OBS. Set the resolution to match your canvas (e.g. 1920×1080) and enable Refresh browser when scene becomes active.

Place it on your ending screen scene. The background is transparent — it layers over your stream.

Streamer.bot — Action 1: Chat emote counter

Trigger Twitch → Chat Message (every message)

Create a new action, add a Execute C# Code sub-action, and paste the contents of Action1_Chat_emote_counter.cs. This runs on every chat message and tallies any emote starting with monkdr, storing counts and image URLs in the global variable emoteUsageCounts.

Streamer.bot — Action 2: Add emote credit

Trigger OBS → Scene Changed → your ending scene name

Create a second action with Execute C# Code from Action2_Add_emote_credit.cs. Before saving, update the file path to point to the folder where your HTML overlay lives:

string path = @"E:\stream\Credits - Simple Scrolling\emotes.json";

Optionally add a Core → Sleep (1500 ms) sub-action after the C# step (see pitfalls below for why order matters).

Confirm the Streamer.bot WebSocket

The overlay connects to ws://localhost:8080 on load. Make sure Streamer.bot's WebSocket server is running — check Settings → WebSocket Server and confirm it is enabled on port 8080.

Troubleshooting

Known pitfalls

Sub-action order: C# must come before Sleep

When the OBS scene changes, the browser source refreshes almost immediately. If a Sleep sub-action runs before the C# action, the overlay fetches emotes.json while the file still contains last stream's data.

[Execute C#] → [Sleep 1500ms]
[Sleep 1500ms] → [Execute C#]

The HTML overlay already waits 2000 ms before fetching emotes.json as a safety margin — the C# write just has to happen within that window.

Global variable format changed — clear it before the next stream

emoteUsageCounts used to store {"emoteName": count} (plain integer). It now stores {"emoteName": {"Count": n, "Url": "..."}}. If you upgraded from the old format, the deserialization will silently return an empty dict on the next run. Open Streamer.bot → Globals, find emoteUsageCounts, and delete or reset it before going live.

Always use persisted = true for global variables

GetGlobalVar and SetGlobalVar take a boolean third argument. Always pass true. Passing false stores the variable in memory only — it won't appear in the Globals UI and is wiped when Streamer.bot restarts, meaning emote counts are silently lost mid-stream. 

CPH.SetGlobalVar("emoteUsageCounts", json, true);  // ✓
CPH.SetGlobalVar("emoteUsageCounts", json, false); // ✗ lost on restart

System.Linq is unavailable — action silently fails to compile

Streamer.bot 1.0.4's C# inline environment does not ship System.Linq. Adding using System.Linq; causes a compile error and the action silently stops running — no error in the log, just nothing happens. Use List<T>.Sort() with a delegate instead of OrderByDescending, and avoid all LINQ extension methods (Select, Where, Take, etc.).

Opening the HTML as file:// breaks emotes.json fetch

Chrome blocks fetch('file://') from a file:// page with a CORS error. The overlay uses a relative path (./emotes.json) which works fine inside OBS's browser source. If you open the HTML directly in Chrome for testing, the emotes section will silently fail — this is expected and only affects local dev.
