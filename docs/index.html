Emote Counter

Streamer.bot actions to track & display top channel emotes

View on GitHub

Overview

How it works

Two Streamer.bot C# actions do the work. The first counts channel emote usage on every chat message. The second fires when your ending scene activates and snapshots the top emotes — with image URLs — to a emotes.json file that any overlay can read.

The included Scrolling Credits for SB.html is an example integration showing how to consume that file inside an OBS browser source. It is not the main product — you can wire the JSON output into any overlay you already use.

Setup

Step-by-step guide

Streamer.bot — Action 1: Chat emote counter

Trigger Twitch → Chat Message (every message)

Create a new action, add an Execute C# Code sub-action, and paste the contents of Action1_Chat_emote_counter.cs. This runs on every chat message and tallies any emote starting with monkdr (case-insensitive), storing counts and image URLs in the persisted global variable emoteUsageCounts.

Adapt the emote prefix filter

By default Action 1 only counts emotes whose name starts with monkdr. Change this to match your own channel emote prefix in Action1_Chat_emote_counter.cs:

if (!emoteName.StartsWith("monkdr", StringComparison.OrdinalIgnoreCase)) continue;

Replace "monkdr" with your prefix, e.g. "pb" or "myemote". The check is case-insensitive, so "PB", "Pb" and "pb" all match. To track all emotes regardless of name, remove the line entirely.

Streamer.bot — Action 2: Write emotes to file

Trigger OBS → Scene Changed → your ending scene name

Create a second action with Execute C# Code from Action2_Add_emote_credit.cs. Update the output path to a folder your overlay can reach:

string path = @"E:\stream\Credits - Simple Scrolling\emotes.json";

On trigger, it reads emoteUsageCounts, sorts by usage, and writes the top 5 to emotes.json as an array of { Name, Count, Url } objects. It then resets the global for the next stream.

Optionally add a Core → Sleep (1500 ms) sub-action after the C# step — see the pitfall below about order.

That's all that's required. The two actions are self-contained — no overlay dependency.

Using the example overlay

Scrolling Credits for SB.html is a reference implementation showing one way to consume emotes.json. If you want to use it:

Add the OBS browser source

Add Scrolling Credits for SB.html as a browser source. Set the resolution to match your canvas (e.g. 1920×1080), enable Refresh browser when scene becomes active, and place it on your ending screen scene. The background is transparent.

Make sure the output path in Action 2 points to the same folder as the HTML file so the relative ./emotes.json fetch resolves correctly.

Confirm the Streamer.bot WebSocket

The example overlay connects to ws://localhost:8080 to pull the full credits data (followers, subs, etc.). Check Settings → WebSocket Server in Streamer.bot and confirm it is enabled on port 8080.

Troubleshooting

Known pitfalls

Sub-action order: C# must come before Sleep

When the OBS scene changes, the browser source refreshes almost immediately. If a Sleep sub-action runs before the C# action, the overlay fetches emotes.json while the file still contains last stream's data.

[Execute C#] → [Sleep 1500ms]
[Sleep 1500ms] → [Execute C#]

The example overlay already waits 2000 ms before fetching emotes.json as a safety margin — the C# write just has to happen within that window. If you use your own overlay, build in a similar delay after the scene change.

Global variable format changed — clear it before the next stream

emoteUsageCounts used to store {"emoteName": count} (plain integer). It now stores {"emoteName": {"Count": n, "Url": "..."}}. If you upgraded from the old format, the deserialization will silently return an empty dict on the next run. Open Streamer.bot → Globals, find emoteUsageCounts, and delete or reset it before going live.

Always use persisted = true for global variables

GetGlobalVar and SetGlobalVar take a boolean third argument. Always pass true. Passing false stores the variable in memory only — it won't appear in the Globals UI and is wiped when Streamer.bot restarts, meaning emote counts are silently lost mid-stream. 

CPH.SetGlobalVar("emoteUsageCounts", json, true);  // ✓
CPH.SetGlobalVar("emoteUsageCounts", json, false); // ✗ lost on restart

System.Linq is unavailable — action silently fails to compile

Streamer.bot 1.0.4's C# inline environment does not ship System.Linq. Adding using System.Linq; causes a compile error and the action silently stops running — no error in the log, just nothing happens. Use List<T>.Sort() with a delegate instead of OrderByDescending, and avoid all LINQ extension methods (Select, Where, Take, etc.).

Opening the example HTML as file:// breaks the emotes.json fetch

This only affects the example overlay, not the C# actions. Chrome blocks fetch('file://') from a file:// page with a CORS error. The overlay uses a relative path (./emotes.json) which works fine inside OBS's browser source. If you open the HTML directly in Chrome for testing, the emotes section will silently fail — this is expected and only affects local dev.
